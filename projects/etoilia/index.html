The project

Morning and evening routines become missions. Each mission earns stars that grow a magical companion through five stages, with outfits, backgrounds and an illustrated album. The child navigates places and objects, with no text at all.

The whole project is co-written with Claude Code: 279 of 292 commits carry its signature. The 363 images are AI-generated, then processed by scripts.

What I did with AI

  • Characters that stay the same

    A panel of 8 agents established that the seed has no effect on this image model. Hence the method: a model sheet first, then every image anchored on an attached reference, changing one thing only.

  • A jury of agents for each companion

    For each new companion, agents propose three concepts and a judge agent picks one. The resulting bible fixes the 5 stages, 18 accessories, 15 backgrounds and the hex palette.

  • A hook that blocks any red push

    A Claude Code hook runs the test suite before every `git push`. A second check rejects a skipped test, a vanished assertion, or a changed test that still passes on the old code, replayed in a worktree.

  • A spec that cannot lie

    The 1,230-line functional spec is checked by the tests: if its version or the game economy figures drift from the code, the suite turns red.

  • Multi-agent code reviews

    A review on 11 axes, each finding cross-checked, found 65 gaps between docs and code. A second review produced 5 batches of fixes, one commit per batch.

  • Project memory

    A 1,045-line CLAUDE.md, including a section of lessons learned the hard way, and a 4,921-line log let the agent resume without relearning anything.

What was hard

The green eye on a green background

The problem
Colour-key removal left green on the edges, between the cat's flames, and erased its green eye.
What I did
Switched to an AI cut-out model (rembg), and added a prompt rule: the background colour must never appear on the character.
The result
Clean cut-outs on all 3 finished companions, with no manual touch-up.

Judge and party

The problem
The model writing the code called 3 red tests "expected" and offered to change them.
What I did
A mechanical rule instead of a judgement call: every changed test is replayed against the old code, and the push is refused if it still passes.
The result
The guardrail even refused its own commit, on a false positive that was fixed straight away.

The old iPad

The problem
The family tablet is stuck on iOS 12. Safari 12 silently ignores part of modern CSS.
What I did
A tool-driven inventory rather than guesswork, then a "simulated old Safari" in the end-to-end tests.
The result
Zero pixel difference across 60 measured elements, and a test that breaks if the fix is removed.
