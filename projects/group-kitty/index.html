Secure online fundraiser

A self-hosted fundraiser built in parallel by two models from the same brief, then taken to production with real payments.

Category
Apps

TechnologiesNode.js, Express, EJS, SQLite, Stripe, PayPal, nginx

The project

Friends leave a message and pay on the provider's secure page. Only the total is public. The site ran 17 days in production and got through a payment-provider incident without downtime.

What I did with AI

  • Two models competing

    The same brief launched a minute apart on two models. The version kept brought a simulation mode, an admin console and zero browser-side JavaScript.

  • Payment security

    Signed webhook, idempotency, payment cross-checks, a restricted key, a maximal security policy, and a server that refuses to start with a dangerous configuration.

  • The provider's AI tools

    The payment provider's official MCP server and skills, plugged into Claude Code.

The problem

The result
2 fixes, a plan B switchable in 4 lines of configuration. The campaign ran to completion.
