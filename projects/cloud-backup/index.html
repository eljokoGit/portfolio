The project

The app drives rclone to back folders up to the cloud. It simulates first, shows the figures, asks for approval, then runs and checks independently.

When the cloud's official client destroyed thousands of files, the investigation rebuilt its internal workings until it explained the destruction, SQL query by SQL query.

What I did with AI

  • A handover that sets the rules

    The handover prompt to Claude Code sets three rules: verify instead of assuming, test with real rclone not mocks, never bypass protections. And: "tell me when you are not sure".

  • A tool-driven forensic method

    Reading rclone's source to refute a hypothesis, dating by the NTFS journal, controlled single-variable tests, a statistical sequence test, reading the SQL in clear from a debug build.

  • Two agents in parallel

    Claude Cowork indexed and cross-referenced the data, Claude Code analysed the database. Case files are written to be reloaded after every compaction.

  • Refuted hypotheses are kept

    A dedicated table keeps the 11 refuted hypotheses, and the AI's own corrected mistakes.

  • Proof of completeness after every transfer

    Both sides are listed again after each transfer. Anything missing marks the run as incomplete and becomes a plan that can only add files, never delete.

  • Deletions capped by the approved plan

    Every transfer receives the number of deletions I approved as a hard cap. On the test bench, three extra local deletions were refused and the files kept.

  • A test bench with the real tool

    The bench runs the real rclone against a local remote, with 3,000 generated files and 11 checks, so every rule is tested without touching the cloud.

What was hard

A rule that would have destroyed everything

The problem
5,095 photos destroyed by the official client. Deleting the temporary files looked like the fix.
What I did
Reading the internals: every temporary file was indexed with the cloud identifier of its target.
The result
The rule would have destroyed 12,801 files, locally and in the cloud. It was corrected before anything was done.

A success with 5,386 missing files

The problem
A sync reported as successful left files behind, and eight local reproductions were clean.
What I did
The defence shipped anyway: a completeness check after every transfer.
The result
205,000 files checked in 45 seconds, and a scheduled drift check.
