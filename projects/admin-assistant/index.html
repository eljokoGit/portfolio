The project

In Spain, a self-employed person files quarterly returns, keeps registers and issues invoices numbered without gaps. For a self-employed person in my household, I built an assistant that does the watching and the paperwork, while I make the decisions.

A Claude session acts as the orchestrator. Scheduled tasks run weekly, monthly and quarterly and drop their findings into an inbox. At the start of each session, the orchestrator checks every new finding against the files before telling me anything.

What I did with AI

  • An inbox between tasks and session

    A task that only writes in a chat loses its finding when the window closes. Every finding becomes a dated line with its task, severity and status. No duplicates, and a line is closed with a date when the problem is gone.

  • A finding is a hypothesis, not a fact

    Before relaying anything, the orchestrator searches the register of settled topics and checks at least one figure in the files. A task that writes "this is not a false alarm" is certifying itself: that is exactly where it must check.

  • One register of decisions and actions

    Numbered actions and decisions, an index of settled topics and an archive. The assistant proposes and puts a figure on every proposal. I decide, and nothing on the tax side is done without my approval.

  • Invoices with no gaps

    Invoices come out of a generator that takes the next free number, refuses a series that does not match the client or a total that does not add up, and warns if the invoice spills onto a second page. The ledger and the number register are updated each time.

  • Stay on my topic

    The orchestrator answers my question first and mentions inbox news at the end. It never switches topic because an item "fits": that rule is written down because it had happened.

  • Scripts that file nothing

    The quarterly scripts reproduce the returns already filed, to the cent, and print that they file nothing. The document sorter only simulates unless explicitly told to act.

  • A register sized for the context

    At 58,000 characters, the register no longer fit in a single read, which broke the first step of the guardrail. It was split into a live register and an archive, with a check that every ID survived.

What was hard

The false alarm

The problem
A scheduled task raised an urgent alert that would have tied up about 2,400 euros for nothing. It was relayed without being checked.
What I did
A written guardrail: a finding is a hypothesis. The register and at least one figure are checked before anything is relayed.
The result
Only what is really left to do reaches me.

A settled topic sold as new

The problem
A reminder about a topic already decided was relayed as a discovery.
What I did
An index of settled topics, one line per closed decision, searched before relaying. Reopening a topic must be announced as such.
The result
Settled topics no longer come back disguised as news.

Six estimates in three weeks

The problem
An annual tax estimate was recomputed on incomplete data and changed six times in three weeks. The moving number cost trust in the whole file.
What I did
The estimate is frozen as a range, recomputing it is forbidden, and a single dated review is planned once the year is closed.
The result
One stable range instead of false precision.

A rule contradicted by the first real invoice

The problem
A declaration rule had been written from reasoning. The first real invoice received showed the opposite.
What I did
The rule was corrected, dated and now cites the document it rests on.
The result
A real document always beats reasoning.
