VERI*FACTU invoicing

Invoicing software compliant with the Spanish tax authority's anti-fraud standard, written from the official documents only and proven against the real test environment.

Category
Apps
Period
July 2026
Status

TechnologiesTypeScript, Node.js, SQLite, SOAP, mTLS, XSD

The project

From 2027, Spanish freelancers must invoice with software that chains every invoice and sends it to the tax authority. I built this software for a freelancer in my household.

Each invoice is cryptographically chained to the previous one and sent with the taxpayer's certificate. Every building block was validated against the administration's real test environment.

What I did with AI

  • A standard read with field-level traceability

    11 official documents archived, a 676-line spec with 215 document-and-page citations. In the code, each field carries its XML path and page. Written rule: do not trust an LLM's memory, Claude's included.

  • Official vectors before code

    The 3 official hash test vectors were recomputed before writing a single line. 5 of 8 open questions were settled by experiments in the test environment.

  • Legal analysis before architecture

    Reading the penalty regime and the software-producer status with AI. Conclusion: portable software, used by the taxpayer with their own certificate, and no distribution before a lawyer's opinion.

  • Agents for the paperwork

    11 scheduled tasks prepare the quarterly filings and write their findings to an inbox. A session triages them, a human decides. Scripts prepare and simulate, they never file anything.

What was hard

The 240 seconds the documentation left out

The problem
The official error file was truncated. The real timestamp tolerance was unknown.
What I did
Targeted test submissions in the administration's environment.
The result
Measured tolerance: 240 s. Resulting architecture rule: generating, hashing and sending form one indivisible unit.

An error used for idempotency

The problem
After a network drop, there was no way to know whether the tax authority had received the invoice.
What I did
Replay the identical XML. If the authority already has it, it answers "duplicate" with the original state, which the tool reconciles.
The result
Zero duplicates, and the verification code is preserved. Tested in unit tests and for real.
