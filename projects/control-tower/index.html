Agent control tower

A pixel-art screen that shows, live, every Claude session, scheduled task and server request, and the questions waiting for my answer. Built in two days with Claude Code.

Category
Agent systems
Period
October 2026
Status
In service on the agents' VM, checked from my phone

TechnologiesNode.js, SQLite, Server-Sent Events, Claude Code hooks, Python, systemd

The project

With a dozen agent sessions spread across my PC, the agents' VM and the server, a question could wait for hours without me seeing it. The tower shows one floor per topic, one character per session, and a quest board for everything that waits for me.

Each quest links to its session, and I answer there. The screen has no write action at all, so no program can approve anything in my place.

Claude Code hooks send only the essentials (state, tool, question), never commands or content. A planning view gathers the scheduled tasks of the VM and of the PC, with failures in red.

What I did with AI

  • Hooks as sensors

    8 Claude Code events, from session start to session end, are sent asynchronously, so a session is never slowed down. A question asked with the question tool, a permission request or a last message ending with a question becomes a quest.

  • Read-only by design

    The screen only shows. Only https links are kept, everything is displayed as text, and incoming events are checked for their host and origin.

  • Reviewed by another agent

    The agent that runs the server reviewed each delivery before installing the service. Its remarks became commits: host and origin checks, and a delivery script that refuses uncommitted code.

  • A mockup before the code

    The design and then the pixel-art look were validated on mockups before any code. Sprites are grids of letters, one colour each, and a pixel font judged hard to read was replaced the same day.

  • The server joins in

    The server agent posts its request queue whenever it changes. That source is accepted only from the host itself: a test from any other device of the private network is refused.

From a question to my answer

  1. An agent asks Question, permission, choice
  2. The hook reports The essentials only
  3. A quest opens On the board, with its link
  4. I answer In the session itself
  5. The quest closes Counted in today's score

What was hard

Events lost to an antivirus

The problem
Some hook events from the PC never reached the tower, without any visible error.
What I did
Traced to an environment variable set by the antivirus that made Python's standard HTTP library fail. The hook switched to a lower-level client and now logs its errors.
The result
No more lost events, and a failure leaves a trace instead of disappearing.

Orphan questions

The problem
A session killed without closing properly left its question on the board for good.
What I did
The hook now attaches the list of sessions still open on the PC. The tower ends those missing for two minutes and closes their questions.
The result
13 vanished sessions ended at once, and the one still alive was left untouched.
