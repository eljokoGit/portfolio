Teams meeting recorder

A Chrome extension that turns a Teams meeting into one structured PDF: live captions, my notes and screenshots, with no audio. Built with Claude Code from a written spec, one milestone at a time.

Category
Apps
Period

TechnologiesChrome extension (Manifest V3), JavaScript, MutationObserver, Shadow DOM, jsPDF, Claude Code

The project

In a large industrial group, I wanted a trace of each meeting that agents could read afterwards. The extension reads Teams' live captions in the browser, adds my notes and screenshots, and produces one PDF when the meeting ends. It records no audio and sends nothing to a third party.

I wrote the spec first: 13 sections, 7 milestones, acceptance criteria and a list of what not to do. Claude Code built it one milestone at a time and stopped after each with a test plan. I tested in real meetings, and nothing moved on without my validation.

The screenshots show the real extension on a fictitious meeting played by a local page: the badge, the side panel, the diagnostic and the PDF it produced.

What I did with AI

  • A spec, then milestones with a stop

    My first instruction: read the whole spec, stop after each milestone, and ask instead of working around a problem. Before writing code, Claude flagged two flaws in my spec: a storage choice that made crash recovery impossible, and a 20-second alarm that Chrome does not allow.

  • 50 agents looking for the flaw

    After each milestone, a workflow of review agents read the code against the spec. Each finding had to come with a failure scenario. On the first milestones, other agents tried to refute them: 3 out of 3 refuted on the skeleton, 8 out of 16 kept on caption capture.

  • Instruments to bring reality back

    Claude cannot attend a meeting. So the extension carries its own instruments: a selector diagnostic, an event log, and a DOM capture that leaves out private messages. I paste the output, Claude fixes against the real page. That is how an unplanned confirmation dialog showed up in the caption language switch.

  • A wrong assumption, caught

    Claude removed a permission on a wrong assumption and broke screenshots. After my test, it admitted the error, then weighed three options before coding. The one I approved takes the shared content straight from the page, with no new permission. I had refused access to all sites: the only site permission is still the meeting domain.

  • A PDF written for agents

    Notes and transcript live in separate sections, each opened by a sentence that says what it contains. Markers such as [NOTE 2] and [CAPTURE 1] survive text extraction. My notes come first because they sometimes carry instructions for the agents that read the file. I set aside the planned AI summary: interpretation happens downstream.

What was hard

Recycled lines

The problem
In a real meeting, the captions lived in a virtualised list that detaches and reuses lines as it scrolls. The spec treated a detached line as final: duplicates and losses were certain.
What I did
I asked for the strategy before any code and refused one of its signals, because a sentence can appear in one piece without being a repeat. Claude replaced node tracking with a register indexed on content, and added decision counters to the diagnostic.
The result
On a 3-hour real meeting: 1,959 lines, 2.9% residual duplicates, no gap. Merging the remaining duplicates stays off by default: the PDF keeps everything captured.

A title that never existed

The problem
A PDF came out under the name of a chat instead of the meeting. The two title selectors written at milestone 1 had never matched, and a fallback hid it.
What I did
The diagnostic now lists every candidate selector that has never matched since installation. A DOM capture in a real meeting then proved that Teams does not expose the meeting subject in the page at all.
The result
The tab title, cut to its last segment, became the only source. The six dead candidates left the code, kept as comments with the date and the reason.

No invented timestamps

The problem
Against a commercial tool on the same 36-minute meeting, the extension captured more lines, 428 against about 300. But it showed 3 minutes without a line, then about 50 lines stamped with the same second.
What I did
Claude showed that the gap and the block were mostly the same speech, displayed late by Teams. Rule: no interpolation. The outage is logged, the badge warns during the meeting, and the PDF frames the block with the only time range that is certain.
The result
Tested on a bench that simulates the caption list. Validation in a real meeting is still pending.
