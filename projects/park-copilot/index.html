Theme park day copilot

An app that runs two theme park days minute by minute. When the plan breaks, it writes the situation up for Claude, which replans, and a checker verifies.

The project

The app answers one question: are we on time, and what do we do next? It tracks wait times across the whole park every 5 minutes and compares real time with the plan. Tested at Disneyland Paris, with my family, in early September 2026.

It never decides alone. When the plan derails, a button copies a quantified brief for Claude. Claude replans, the server checks the result against 16 rules, and the phones update within about ten seconds.

What I did with AI

  • A prompt written by the app

    The brief starts with the command that loads the replanning method, holds the day's state, rules and live waits, and ends with the parent's comments, which take priority. Test: Claude must be able to answer without asking a single question.

  • The method in a skill

    A 336-line Claude Code skill sets the order of options (reorder, compress, pay for a skip-the-line pass, remove only with consent), a 7-step procedure and a 4-block answer readable on your feet.

  • 16 rules the server enforces

    Constraints are functions, 12 of them blocking: a plan that breaks one is rejected and nothing is saved. Tested on 7 deliberate violations, all rejected.

  • Exhaustive search against the model's intuition

    A tool generates and checks all 800 possible days in 600 ms. Claude can no longer claim an option is best unless the ranking shows it.

  • A review by 9 agents

    9 reviewers produced 224 raw findings, narrowed to 14 verified findings before fixing.

The result
800 days checked in 600 ms. The model argues from a ranking, no longer from a hunch.
