Studio d'images en IA locale

Des modèles ouverts sur mon propre serveur GPU, pilotés depuis une interface de conversation que j'ai conçue : je tape une idée, un LLM local en fait un prompt détaillé, le GPU la dessine.

Le projet

Je me suis lancé dans l'IA locale : ComfyUI pour les graphes de génération d'images, WorkflowUI pour publier ces graphes comme de petites applications, et un LLM local pour le texte. Pour m'en servir au quotidien, j'ai conçu ma propre interface, une conversation où chaque message devient une image.

C'est un petit service FastAPI avec une page Alpine.js. Le navigateur ne parle qu'au service. Le service appelle une liste fixe de routes de WorkflowUI et lit ComfyUI sans jamais y écrire.

Les captures viennent d'une copie avec des conversations de démonstration. Les prompts réécrits qu'elles montrent sont illustratifs : cet affichage est construit et testé, et sera activé avec la prochaine version du workflow.

Ce que j'ai fait avec l'IA

  • Enregistrer le vrai serveur avant de coder

    Claude a d'abord exploré WorkflowUI en lecture seule, sa description d'API et son code front, pour trouver le format exact des requêtes. Il a ensuite enregistré une vraie génération complète, puis les cas d'annulation, d'erreur et de génération inconnue. Le code n'est venu qu'après.

  • Des comportements cachés, mesurés

    Sans ses liaisons de champs, WorkflowUI répond 200 mais lance les valeurs par défaut. Un graphe peut annoncer un succès sans image. Une réécriture ratée renvoie en silence le prompt tapé. Chaque piège a été mesuré, écrit, puis transformé en règle.

  • Un LLM local dans la chaîne

    Chaque idée est réécrite par un LLM local avant la diffusion. Une copie du workflow expose le texte réécrit, et un correctif de 4 lignes sur le nœud de réécriture fait vraiment relancer la réécriture par le bouton Relancer.

  • Une liste blanche, pas un proxy

    Les routes d'administration de WorkflowUI sont ouvertes sur le réseau local : le service ne doit jamais relayer d'appel arbitraire. Il connaît 12 appels WorkflowUI et 2 appels ComfyUI en lecture seule, et borne chaque valeur : une image par génération, des tailles jusqu'à 2048 pixels.

  • Des tests sans GPU

    58 tests tournent en moins d'une seconde. Ils rejouent 24 réponses enregistrées sur le vrai serveur, erreurs comprises, sans aucun faux serveur écrit à la main.

  • Une progression honnête, pas de message fantôme

    La progression est poussée en direct et estimée à partir des 100 dernières générations ; elle s'arrête à 95 % jusqu'à la vraie fin. Chaque message est enregistré avant le lancement et retiré si le serveur le refuse.

Le problème
Au premier essai, WorkflowUI a répondu 200 mais a généré ses valeurs par défaut : la requête n'avait pas les liaisons de champs, et rien ne le signalait.
Ce que j'ai fait
Claude a lu le code front pour trouver le corps exact, puis chaque appel a été enregistré sur le vrai serveur et rejoué dans les tests.
Le résultat
Le service envoie toujours les liaisons, et un test casse si elles disparaissent.

Un succès sans image

Le problème
ComfyUI peut annoncer une génération réussie alors que la branche image a été rejetée : un seul nœud de sortie valide lui suffit.
Ce que j'ai fait
Une règle dans le service : une génération terminée sans image est une erreur, affichée dans la conversation.
Le résultat
Un réglage invalide apparaît désormais comme une erreur claire en 1,5 seconde, au lieu d'un succès vide.
